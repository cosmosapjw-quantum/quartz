# R2. Primary evidence, original code and transport limits

1. Silver et al. (2016), *Mastering the game of Go with deep neural networks and tree search*, Nature 529, https://www.nature.com/articles/nature16961 : expert-move supervised policy softmax combined with an MCTS edge prior; source of policy-learning idea, not proof of Gomoku15 transfer.
2. Chaslot et al. (2008), *Progressive Strategies for Monte-Carlo Tree Search*, https://project.dke.maastrichtuniversity.nl/games/files/articles/pMCTS.pdf : progressive unpruning exists, so candidate reopening is NOT novel by itself.
3. Jin, Duan, Hang (2025), *Rapfi: Distilling Efficient Neural Network for the Game of Gomoku*, https://arxiv.org/abs/2503.13178 : pattern-lookup MixNet distillation, incremental updates and finite-time alpha-beta / PUCT evaluation. Their policy + value heads and large Katagomo-derived dataset do not become a QUARTZ-compatible ONNX policy by merely holding compressed mix9svq weights.
4. QUARTZ C14 final, docs/research/cognitive_metareasoning_20261120/highbranch_transfer_14/RESULTS_AND_NEXT_KO.md and NEXT_STAGE.json (parent eaff0ae): 192 real QUARTZ 15x15 CPU MCTS, 48 external Rapfi, stress 12/12 tactic-positive, neutral 0/12 teacher-agreement and per-stratum 10% CPU mismatch FAIL. Reuse game legality and same-tree [AtomicU64;4] code, but NOT its 24 public test roots for learning.
5. Actual code read at parent: src/games/gomoku15.rs board_as_12 (1 black, 2 white); src/mcts_server/highbranch14_cpu_server.rs previously UniformEval with geometric top16, not trained; src/gomocup_bundle.rs has optional 17x15x15 ONNX policy-value interface, but neither ONNX checkpoint nor torch/onnx modules were present in the inspected worktree.

Reuse decision: build a distinct supervised log-linear legal-action policy, with explicit frozen weights and policy-only value=0. This is a lower-capacity surrogate to discriminate model availability from search control, NOT evidence for strong Gomoku play or a stand-in for the Rapfi native architecture.
