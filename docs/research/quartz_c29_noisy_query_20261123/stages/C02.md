# C02: equations to code and actual GameState adapter boundary

FactorBayes: q[2] for Z signs, locals[n][2][3] for candidate utilities, known flags for exact compatibility. init uses p_i(u)*(1+z*r_i*f_i(u)), observed noise updates only queried i's conditional law and q, leaving other candidate-local laws unchanged. Enumerated worlds remain independent of implementation for test-only oracle.

Planner T(h) is max known incumbent and all posterior candidate means. H1 and H2 compute STOP vs cost-adjusted sum over channel outputs. A posterior-only change of m is explicitly rejected as a state compression. Strictly identity observation plus known-only terminal is a separate compatibility contract; repeat already-known candidate forbidden only in this mode.

Actual GameState bridge reuses same C26 board, deterministic cue seed, four rollouts and paid initial exact child verification. Subsequent noisy observations are NEW rollouts of that candidate's child state and are charged by entered nodes. A 3-by-3 fitted channel maps exact minimax utility to single rollout outcome; its calibration status and conditional-independence limitations must remain explicit. Offline exact minimax final outcome for evaluation runs only after controller returns its action, never as an input to the belief update. Expected planning cost is calculated from already observable cue_nodes/4 times original lambda=1/1024; actual query nodes may differ and are reported separately.
