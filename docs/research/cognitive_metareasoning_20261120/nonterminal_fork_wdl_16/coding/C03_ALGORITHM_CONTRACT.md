# C3. Fixed finite algorithm and error budget

Exact evidence rules:
1) Early reject any root with W_t(s) nonempty, W_o(s) nonempty, terminal board or <16 legal moves; a move that wins immediately is not a candidate for the nonterminal certificate.
2) For each omitted a sorted by actual trained full-legal prior, hypothetically add t at a, and test the at-most32 empty indices that are collinear (four axes × both signs × distances1..4). A c is an immediate win iff the actual five-in-row checker on s+a accepts c. Once TWO DIFFERENT winning cells found, return a verified pair; stop collecting after four certified actions. Certificate may be empty.
3) On proof positive, normal gating arm adds candidate to the existing root mask (not a new edge) after first 8 visits, preserves all N/W/M2/P and exact model state; sham adds same number of non-certified omitted legal moves. Explicit proof-choice arm follows same mask/search and returns the original certified a as a separate intervention, distinct from MCTS action.
4) Physical runtime cap: fixed target 20ms, 8 visits up front then one root visit per continuation iteration until budget or2048 visit cap. Count full evaluation, board proof, root setup and MCTS; output serialization and reading model weights not counted. If initial proof alone exceeds budget record overshoot, no fictitious equal CPU. For full legal baseline no proof scan, so achieved cost equality must be checked ex post per stratum.
5) Reproducible seed17 (same C15 code), varied opening source seeds upstream. Predeclared primary root arms learned_full, learned_fork_mask, learned_sham_mask, learned_fork_proof_choice, learned_top16; experiment order rotated across source ID rather than fixed fastest-first.
6) Paired-game contrast: each pre-frozen history h is used twice: intervention as black and as white (other player learned_full), model identical and every move 20ms target CPU. Report WDL per pair, total moves and proof triggers. Use game outcomes, not finite teacher moves.
7) Error classes: board-rule error, stale model hash, root statistics corruption, source family leakage, CPU mismatch, terminal timeout/resource cap, low activation support, lack of game WDL. Scientific acceptance does not downgrade a real negative outcome.
8) TDD: focused negative behavioral test that a nonterminal double-endpoint board gives correct witness, but existing C15 oneply logic gives no such witness; observe red because new endpoint absent, then implement and prove green. Additional tests on single endpoint, opponent immediate win, boundaries and rotated boards.
